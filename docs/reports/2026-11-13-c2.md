## 4. Findings outside the five items

1. **Attempt 1's report does not exist.** The previous run claimed `docs/reports/2026-11-13-c2.md` committed on
   `kanban/t_c961f897`. No `docs/` directory, no such file, and no commit touching `docs/reports` exists on any
   branch of this repo (`git log --all --name-only -- docs/reports/*` is empty). Treat that claim as lost, not
   as delivered; this file is the document of record.
2. **The README was still the stock Vite template** — no way to learn that the app needs seven `VITE_*`
   variables or it renders blank. Fixed in this PR (README "Running locally" section + `.env.example` with
   names only, no values).
3. **The local-network/CI split is a real trap:** the values needed to run locally are only in the `dev`
   environment's Actions variables, which the `gh` CLI cannot read with the available token scope
   (`GET /repos/.../actions/variables` → 404). They are recoverable, because they are compile-time and appear
   in the CI build log and in every shipped bundle — that is how the local run was configured here.
4. **Dev is one build behind `main`.** Live dev = `ac5f800`; `main` tip = `4fb95e0`, whose run was cancelled.
   The missing commit is the G2 static `noindex`/`robots.txt` change, so that half is **not yet on dev**
   (`curl` of the live `index.html` shows no `robots` meta). Not ours to fix, but the pipeline owner should
   re-run it.
5. **The dev API host serves the stock Functions placeholder at `/`** (`200 text/html`, "Your Azure Function
   App is up and running.") — cosmetic, noted only because it makes a `GET /` look like a healthy app.
